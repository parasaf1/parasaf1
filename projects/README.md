## Delivery workflow

| Stage | Meaning |
| --- | --- |
| Backlog | Candidate improvement; scope or feasibility not yet agreed. |
| Planned | Proposed next scope; acceptance criteria and dependencies must be agreed before implementation. |
| In Progress | Work reported underway in public engineering evidence. |
| Testing | Implementation awaiting defined verification; only mark testing results after evidence is available. |
| Completed | A narrowly scoped capability or milestone has documented verification; does not imply release. |
| Released | Explicit release evidence confirms deployment or availability for the stated scope. |

The proposed roadmap items are directional, not promises of features or dates. Public status is based on the linked evidence and can lag private development. No private tasks, prompts, source code, credentials, internal topology or user data are published.

## Maintenance

Review public project metadata and case studies before changing status. Record evidence and its scope when marking an item completed or released. Update these documents only with sanitized, owner-approved information.
